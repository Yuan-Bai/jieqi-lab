# 跨批次网络评估缓存可行性测量

> 公开副本说明：个人绝对路径已改为相对路径或占位符；标注“未随源码分发”的实验材料仅作为历史记录，不能从本仓库下载。复现命令中的 `<PROJECT_ROOT>` 等占位符需替换为自己的路径。

日期：2026-10-06。结论：**暂不接入生产缓存**。

本次只增加旁路测量工具和测试，没有复用网络输出、压缩未命中批次、
合并搜索统计，或修改生产训练配置。此前的机会分支按需创建仍保留。

## 结论

- 同局、跨网络调用的实际输入重复率上限约 **7.215%**；4096 条 LRU
  命中率 **6.436%**。这不是自博弈加速比例。
- 105,743 次重复输入输出比较中，40,402 次 policy 或 value 不逐位一致
  （38.208%）；最大 policy 分量差异 0.00132519，最大 value 差异
  **0.00771169**。仅凭输入相同，不能保证返回历史输出等价于当前调用。
- 即使同时要求批大小相同，23,756 次比较中仍有 5,316 次 policy 不逐位
  一致，最大差异 3.57628e-7；该组 value 全部一致。
- 完整输入批次连大小、行顺序都完全相同的重复仅 **2 次 / 29,647 次调用**，
  全部是根评估，没有重复的完整叶批次。保留完整批次上下文的保守缓存
  机会很少，不值得优先实施。

这不证明缓存会使学习效果变差或需要更多数据；它证明目前不能沿用
“相同输入可原样复用输出”的精确等价论证。按照不影响训练结果的要求，
本轮停在测量阶段，不开启近似缓存，也不改变 TF32、批大小或搜索预算。

## 测量条件

原始结果：
results.json（本地实验产物，未随源码分发：`data/pilots/network_cache_20261006_204415/results.json`），
results.jsonl（本地实验产物，未随源码分发：`data/pilots/network_cache_20261006_204415/results.jsonl`）。

- 模型：`data/train_rules5_20261004/models/training_checkpoint.pt`，iteration 16；
  实验过程中权重冻结，网络保持原来的 eval 模式。
- 本机 GPU：RTX 4060 Laptop；PyTorch 2.6.0+cu118。
- 后端：规则 Cython、合法着 Cython、节点 Python；父进程与 spawn worker
  均验证实际后端身份。只保护实际加载的二进制，不要求可选节点编译模块。
- 32 局、8 worker、种子 20264000 至 20264031；28 局普通预算 800，
  4 局强预算 3200，强局间隔 8；叶批上限 64，批内去重开启。
- 完整机会支持 `chance_k=0`，本次实验启用 lazy chance allocation；
  PCR 关闭，virtual loss 3；matmul TF32 关闭、cuDNN TF32 开启。
- 每局运行原路径和旁路路径各一次，共 64 次完整自博弈。两个 16 局分组

- 所有候选缓存每局重建；不跨局、worker 或模型版本复用。

## 统计口径与结果

直接比较原评估函数编码后的 **实际 float32 输入张量**。每行先做无损压缩，
以完整压缩字节作为精确键；不是只比较状态对象、候选签名或摘要哈希。
候选 LRU 使用现有 `leaf_input_signature`，并对命中执行实际输入字节校验。
本次没有发现候选键合并不同实际输入的断言失败。

候选 LRU 在批次开始时统一查表，再按原输入顺序更新；同批重复不计入
跨批命中。本次观察发生在已有批内去重之后，没有同批重复。

## 输出一致性

原始评估照常执行，旁路复制其返回的 policy/value 用于比较，向搜索返回的
仍是原结果对象。输出比较分别采用两种每局 4096 条 LRU：
只按实际输入，以及按 `(批大小, 实际输入)`。命中后保留首次缓存的输出，
不刷新为当前输出。policy 比较原始 float32 字节，value 比较其返回数值
对应的 double 字节，包含正负零区别。

| 输出审计键 | 比较次数 | policy 或 value 不一致 | policy 不一致 | value 不一致 |
| --- | ---: | ---: | ---: | ---: |
| 实际输入 | 105,743 | 40,402（38.208%） | 40,243 | 20,922 |
| 批大小 + 实际输入 | 23,756 | 5,316（22.378%） | 5,316 | 0 |

输入键比较中的 1,500 次 leaf→root 复用候选全部出现输出不一致。
例：种子 20264001，相同实际输入先在叶批 `B=64, row=5`，随后在根
`B=1, row=0` 被评估；value 从 0.0191365592 变为 0.0191712622，
policy 最大分量差异 0.0002570301。原始 JSON 保留每局前 12 个不一致
案例的批大小、位置、搜索编号和压缩输入摘要，不保存可独立回放的完整张量。

观察到批大小相同但位置不同的 policy 差异；批大小与位置同时相同的
已比较样本未观察到差异。后者没有单独的比较次数分母，不能据此证明
此类键的安全性，更不能证明将未命中行压缩重排后仍等价。

GPU 的批形状相关数值行为是可能解释，但本轮没有切换 TF32 或内核设置
以确定原因，也没有测量这些差异对搜索或训练效果的影响。

## 成本与收益限制

现有候选签名重新构造平均 **4.138 微秒/输入**。下表包含候选查表、
精确字节验证、LRU 更新与淘汰，不包含实际缓存输出复制和额外内存成本。

| 容量 | LRU 操作微秒/输入 | 签名 + LRU 微秒/输入 | 仅 policy 的理论存储 / worker |
| ---: | ---: | ---: | ---: |
| 256 | 1.634 | 5.772 | 2.49 MiB |
| 1024 | 1.453 | 5.591 | 9.96 MiB |
| 4096 | 1.475 | 5.613 | 39.84 MiB |
| 16384 | 1.814 | 5.952 | 159.38 MiB |

存储按每条 2550 个 float32 policy 分量计算，未含输入键、容器或 value。
4096 条若 8 worker 同时满载，仅 policy 约 318.75 MiB；16384 条则约
1275 MiB。现有签名可能有机会复用，以上不是优化后的生产缓存成本。

精确输入压缩键构造累计 217.595 worker 秒，平均 132.447 微秒/输入，
是故意用于验证的昂贵旁路，**不建议照搬到生产热路径**。

审计路径评估累计 419.769 worker 秒。4096 条 LRU 的全命中调用覆盖
14.627 秒，其中根 13.418 秒、叶 1.209 秒；但它们的历史输出不保证等价，
这不能作为可实现的安全节约量。真正完整批次相同的两次调用只覆盖
0.02052 秒，约为该评估累计时间的 0.00489%。

这里的评估时间减掉了旁路 prepare 时间，但包含编码、H2D、网络、softmax
和 CPU 回传，也包含多 worker 的 GPU 等待。不是纯 GPU 内核时间，也不能
直接除以进程池总耗时推导加速比例。旁路仍有 CPU 争用和输出比较开销。

原路径两组耗时 92.662 秒和 149.298 秒，旁路为 103.108 秒和 193.534 秒；
完整实验耗时 539.082 秒。这些数字只说明测量成本，**没有实际缓存提速实测**。
