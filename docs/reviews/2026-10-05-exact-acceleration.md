# 保持训练语义的本机加速（2026-10-05）

已实施纯 CPU 编码和批次装配优化，默认生效，无须调整训练命令。实际 checkpoint 的 CUDA 更新与固定搜索逐位对照通过。没有启用 AMP、改变 TF32 设置、减少模拟数或调整数据分布。

后续已完成策略数组回传与批内重复历史复用，增量结果见 `docs/reviews/2026-10-05-selfplay-lowrisk-acceleration.md`；下文保留首轮编码优化的测量记录。

## 实施范围

- `azero.py`：共享的原位平面填充函数，训练/推理直接分配连续 NCHW 批次，不再逐样本创建输入张量后堆叠。
- 常量平面合并广播；重复历史棋盘使用只读 1KB 查表，按原来的 float64 除法再转 float32 构建，保留舍入结果。完整历史顺序、过滤规则、计数和所有 238 通道不变。
- 训练策略目标在预分配的 NumPy 数组中逐项写入，保留 zip 截断、重复索引最后覆盖、负索引及 FP32 值。没有跳过策略权重为零的样本。
- 不缓存全 buffer 的展开张量、不预取或重排样本、不新增随机调用。单个 1024 输入批次约 87.7MB，避免同时保留逐样本输入和堆叠输入，约少一份批次输入的临时 CPU 内存。
- FP32、NCHW、CUDA 叶批次大小/顺序、去重配置、网络、损失计算、AdamW、梯度裁剪和训练预算均未改变。

`compact_to_tensors` 保留原接口，旧样本兼容路径不变；数据、规则、搜索及 checkpoint 版本未改变。可以沿用 `data/train_rules5_20261004` 的完整 checkpoint、optimizer、scheduler、RNG 与 replay，不用重训或清空 buffer。已经运行的 Python 进程需在下次正常续训启动时加载新代码，不应中途强行热替换。

## 实测

设备：当前 i9-13900HX + RTX4060 Laptop；PyTorch 2.6.0+cu118。基线为私有历史快照（未随本仓库分发）中的 `azero.py`，不是另一次测试的历史耗时。

读取 iteration=10 的完整 checkpoint 和最新回放文件，固定抽取 1024 条原始样本，加入原局、镜像、翻面及镜像翻面，再固定抽取三批 1024 样本。每组交替新旧计时顺序，共六组；完整训练计时各预热三步、测十二步。

| 项目 | 修改前 | 修改后 | 耗时降低 |
|---|---:|---:|---:|
| CPU 构建 1024 样本的输入/标签批次 | 173.23ms | 66.51ms | 61.6% |
| 完整 FP32 训练步，含传输及优化器 | 343.89ms | 251.39ms | 26.9% |
| 8 worker 固定根搜索组的墙钟时间 | 8.8323s | 8.5955s | 2.7% |

训练吞吐约 1.37 倍，CUDA 分配峰值两者均为 1,839,796,224 bytes。按固定批次测试换算，1000 步少约 92.5 秒，仅是优化步骤估计，不包含诊断、回放保存、采样和自博弈。

搜索复用预热的 8-worker 池。16 个根取自两个当前模型的 64-simulation 完整对局，覆盖开局/中盘/后段；每组重复四次并使用不同固定种子，共 64 个根搜索，其中 8 次采用 3200 模拟、其余采用 800，叶批次仍为 64、chance k=0、去重开启。六组对应搜索共 384 对。

这不是完整 1024 局生产轮次计时。搜索改进较小，频率、温度和进程调度有噪声，不能承诺每轮恰好快 2.7%。当前训练时间主要用于自博弈，不能把 1.37 倍训练步吞吐称作整轮吞吐。

## 等价性验收

- [x] 独立标量参考编码器：随机公开状态、完整/不完整/缺失历史、历史容量边界及全部通道字节一致。
- [x] 输入、策略、value、布局和步幅一致；样本不被修改，返回批次之间不共享存储；旧格式缺失字段保持兼容。
- [x] CPU 连续三步 AdamW 对照，包括整个 batch 策略权重为零的情况：损失、梯度、参数、BN 状态及 optimizer 状态一致。
- [x] 当前完整网络及真实 checkpoint 的 CUDA 连续三步对照：三批增强数据的损失、梯度、参数、BN 状态及完整 optimizer 状态逐位一致。
- [x] 384 对搜索：完整策略数组的字节哈希、落子、搜索 RNG 状态、叶计数和机会节点计数全部一致。
- [x] 探针前后验证 checkpoint、latest、train_state、生产日志及最新回放文件哈希，全部未变；不保存试验权重，不添加试验对局。
- [x] 全量 unittest：293 项通过。新增编码回归 7 项通过，`py_compile` 与 `git diff --check` 通过。
- [x] 数据增强/根噪声审计通过；翻面对照 200 局随机对局加 2 个固定规则局面，共 202 对、28651 ply，合法着、终局、规则状态、信息态、样本及张量均零偏差。

该改动只减少相同输入张量的构建成本，没有增加所需训练数据或学习难度的机制。有限测试不是所有未来硬件/软件栈的数值保证；它验证的是当前实现、当前设备与当前精度配置，原有 CUDA 非确定性边界没有扩大。

## 后续边界

- 后续优先检查规则纯函数热点、重复历史表示的同调用复用；必须有同样的动作/输入/更新等价性对照与实际计时。
- 不自动切换叶去重、worker 数或合批策略；即使编码完全一样，CUDA 批次形状改变也可能改变输出及后续搜索轨迹。
- AMP、PCR、降低搜索预算、扩大叶批次、近似缓存/量化均不符合本轮严格保持结果的目标，不接入当前主线。

