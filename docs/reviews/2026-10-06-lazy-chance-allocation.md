# 机会分支按需分配：实现、等价性与本机测量

> 本页保留初始默认关闭阶段的实现与实测记录。验收后用户已选择默认开启（仅 on/k=0）；
> 当前无需追加开启参数，回退用 `--no-lazy-chance-allocation`，见 [当前配置](../performance.md)。下文历史结果与命令不重写。

日期：2026-10-06。承接 `2026-10-06-search-reuse-measurement.md` 的检查顺序。

## 结论

- 实现默认关闭的 `--lazy-chance-allocation`，只允许机会节点开启且 `chance_k=0`。
- 当前检查点的 CUDA 完整逻辑图、网络输入输出、策略、走法、RNG，以及完整对局训练样本均通过配对验证。
- **64 组完整对局合计耗时下降 11.78%，吞吐提升 13.36%**；四批配对耗时下降均值 12.27%。
- 固定局面四轮平均耗时下降 10.06%，合计吞吐提升 11.20%。
- 可以显式开启后在原目录续训；不需要重置优化器、重开训练或清空 buffer。默认及生产配置未替用户改动。
- 本次不实现跨批网络缓存或图搜索，不减少模拟预算，不改变网络前向批次。

## 实现边界

修改 `azero.py`：`AZConfig`/CLI、`NeuralMCTS._expand_node`、机会导航，以及辅助边际采样的补全入口。

1. 扩展时仍创建全部合法动作边，先验归一化复用现有 Python/Cython 方法。
2. 机会边保留完整计数的不可变快照，用内部 tuple 标记表示结果对象尚未全部分配，不增加节点槽。
3. 每次导航仍先按完整模拟世界池抽移动类型，再抽捕获类型；RNG 调用数量及顺序不变。
4. 仅创建这次抽到的结果对象，键使用原 k=0 枚举序号，先验使用原边际计数除法。
5. 路径层数、行动方、访问统计、虚拟损失、价值回传和信息集决策共享均保持原样。
6. 此类分配不算作 `chance_outcomes_added`：这些结果一直属于完整逻辑支持，不是 k>0 遗漏候选的补建。
7. 外部状态与快照不一致时，无 RNG 地恢复 eager 布局，再执行原防御路径；没有扩大合法状态支持或修复其他异常。

`materialize_chance_outcomes` 保留既有节点及共享引用，补上未访问对象并恢复原顺序。
辅助 `sample_outcome` 会先补全该层，不能因物理缓存尚不完整而改变边际分布。
训练搜索不调用此辅助补全；k>0 和机会节点关闭的既有语义不变。

因此，未补全物理树的序列化/节点数不同是预期变化。等价性比较采用补全后的完整逻辑图。
未访问机会结果不参加动作边 PUCT 选择，也不产生叶评估，所以延迟对象分配不减少训练信息。

规则、编码、数据及搜索版本保持不变。旧检查点缺少新配置字段时正常恢复；原有来源校验没有放宽。
CLI、运行配置及评估记录保存开关状态，训练日志区分完整预建与实验性按需分配。

## 正确性验证

定向测试覆盖默认/非法开关组合、全部池中等概率位置、非首次类型优先访问、单/双揭示、明吃暗、
精确先验与原始键、不可变快照、完整辅助分布、已有对象/共享引用保留、异常路径以及回传。
CPU 搜索还覆盖 batch 1/8、去重开/关、virtual loss 0/3、根噪声与策略剪枝。

CUDA 审计使用三条真实神经自博弈轨迹（27/75/54 步）、捕获偏置轨迹和两个受控残局，合计 **24 个局面**。
暗子数 0–30，私有捕获计数 0–8，包含有重复历史的局面。
每局面分别执行 800/3200 两档，**48 组 / 96 次搜索**逐组检查：

- 相同调用顺序与 batch shape 的实际 CUDA 输入、原始 policy logits/value 输出哈希。
- 策略、走法、RNG、叶评估数量及机会导航计数。
- 无 RNG 补全后的整棵图 pickle 哈希，包括未访问节点的先验、全部统计与共享决策引用。
- 输入 state/belief/history 未被改动。

全部一致，每个模式实际输入 **82,678 行 / 1,484 次前向**，机会导航 miss 均为 0。
之后额外计时的 **192 组 / 384 次固定局面搜索**，策略、走法、RNG 和叶/机会计数也全部一致。

完整对局采用种子 `20264000..20264063`，**64 组 / 128 次执行**，其中 56 普通、8 强局，均到规则终局。
每个模式产生 **3,235 ply / 3,235 条原始样本**，最长 100 步；红胜 22、黑胜 39、和棋 3。
8 个强局长度分别为 24/30/67/80/38/82/62/64。
逐局检查完整样本列表（全部 CompactSample 字段）哈希、结局、步数、样本数、叶总量/去重量、最终 RNG，全部一致。
每个模式 pending leaf 总数 **3,522,154**，实际唯一叶评估 **3,407,450**，没有用少评估换取速度。

## 速度

8 worker，先分别热身；四轮顺序 eager→lazy、lazy→eager 交替。计时阶段无输入哈希 hook 或图扫描/补全。
固定搜索采用生产 `return_root=False`，计入建树、GC 和释放；完整对局按实际自博弈逻辑运行。

| 完整对局批次 | eager 秒 | lazy 秒 | 配对耗时下降 |
|---|---:|---:|---:|
| 16 局，第 1 批 | 101.70 | 84.75 | 16.67% |
| 16 局，第 2 批 | 165.09 | 150.04 | 9.12% |
| 16 局，第 3 批 | 159.46 | 142.40 | 10.70% |
| 16 局，第 4 批 | 143.55 | 125.47 | 12.59% |
| 64 局合计 | **569.80** | **502.65** | **11.78%** |

吞吐比 `569.80 / 502.65 = 1.1336`。四批配对下降均值 12.27%，按批次重采样的 bootstrap 95% 区间为 **9.91%–15.18%**。
均值与合计比例采用不同权重，不应把 12.27% 与合计吞吐直接互相换算。
单局 worker 秒合计下降约 10.04%，这是并行累计量，不是整轮墙钟。

固定局面四轮合计 eager 37.45 秒、lazy 33.68 秒；每轮下降 11.78%/7.96%/10.46%/10.05%。
配对均值 10.06%，bootstrap 95% 区间 **8.59%–11.35%**，合计吞吐提升 11.20%。
固定局面两档预算各半；完整对局才采用生产 7:1 普通/强局比例。

## 对象与内存

48 组审计搜索在补全前累计：全部物理节点 **9,410,616 → 2,628,042（减少 72.07%）**；
机会层/结果对象 **6,845,129 → 62,555（减少 99.09%）**，lazy 已分配机会子节点中未访问数为 0。
节点及三个字典的浅层字节累计 **3.424 GB → 0.952 GB**。
这些是跨搜索累计对象/浅层字节，不是瞬时峰值内存，不包含字典键值、标量和计数快照。

同一开局、相同 RNG，在每个模式/预算分别启动全新单 worker，先进行相同残局热身，再保留搜索根读取 Windows 进程内存：

| 预算 | 实际节点 eager→lazy | 进程峰值 RSS MiB eager→lazy | 根存活时 RSS MiB eager→lazy |
|---|---|---|---|
| 800 | 228,402 → 32,593 | 741.5 → 700.8 | 741.5 → 667.3 |
| 3200 | 857,986 → 126,875 | **1034.7 → 759.4** | 1034.7 → 755.7 |

3200 的进程峰值 RSS 下降约 26.6%；根存活相对热身前的 RSS 增量从 390.0 MiB 降到 111.2 MiB。
800 的对应增量为 96.4 → 21.6 MiB。单独四次内存测试的策略、RNG、叶和机会计数也一致。
RSS 包含 Python/PyTorch/CUDA 驱动等，不是纯树大小，不是显存，也不是 8 worker/完整训练的峰值；不能直接乘 8 外推。

## 复现与续训

```powershell
$env:JIEQI_RULES_BACKEND="cython"
$env:JIEQI_SEARCH_BACKEND="python"
$env:JIEQI_LEGAL_BACKEND="cython"
# --output 必须指向已存在目录中的新文件，不能覆盖历史产物。
python tools/benchmark_chance_allocation.py --workers 8 --search-rounds 4 --game-rounds 4 --games-per-round 16 --output data/pilots/NEW_DIRECTORY/results.json
```

原续训命令仅追加 `--lazy-chance-allocation`；继续保留 `--chance-nodes --chance-k 0` 和其余训练参数。
无需 `--reset-optimizer`，不更换目录，不清空 buffer。不传新参数则继续 eager。
建议先在原目录续训 1–3 iter，看真实自博弈秒数、局长及内存，再扩大运行轮数；本次未启动生产训练。
