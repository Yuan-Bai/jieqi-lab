# 当前自博弈 CPU 热点与精确优化候选

日期：2026-10-08。用途：混合精度吞吐复验未过后，重新定位当前搜索中的 CPU 工程成本。
本次只运行既有只读剖析工具并整理文档，没有实现候选优化、训练、修改模型或切换生产后端。

## 结论与边界

可以继续研究不改变精度、采样和搜索行为的 CPU 加速，但还没有新的优化收益数字。
最新生产记录仍是合法着 Python 后端；已验收的合法着编译尚未用上。
本次剖析特意启用合法着 Cython 与机会对象按需分配，定位启用已知加速后还剩什么。
因此这些数字不是原生产后端的成本占比，也不能直接外推 1024 局整轮。

轻量计时中，动作边扩展约 11%，合法着查询约 9%--10%，输入编码约 6%--7%，PUCT 选子约 3%--5%。
信息态快照、确定化和走子更新存在成本，但不是本次最大的单项。
机会结果对象按需分配后，完整揭示分布的重复构造仍然存在，是优先研究的精确 CPU 优化候选。

## 轻量计时结果

占比 = 对应插桩函数累计墙钟 / 同组插桩搜索累计 worker 墙钟。
这是函数边界耗时，不是纯 CPU 资源占用；包含进程抢占、GPU 等候等因素。
不使用组墙钟作分母，也不把不同探针的嵌套项相加。

| 项目 | 800 模拟 | 3200 模拟 | 探针及包含关系 |
|---|---:|---:|---|
| 合法着查询 | 9.39% | 9.98% | `profile.json`，包含攻击回调 |
| 攻击回调（所有调用） | 2.92% | 3.33% | 同上，绝大部分包含于合法着查询 |
| 编码（根+叶） | 6.30% | 7.00% | 同上，包含于网络评估 |
| 叶输入签名 | 0.80% | 1.13% | 同上，不包含事先准备的重复历史条目 |
| 动作边扩展 `PUCTNode.expand` | 11.23% | 11.03% | `expansion.json`，不含 `_expand_node` 之后的按需机会配置 |
| PUCT 选子 `select_child` | 3.26% | 4.63% | 同上，包含 Q/U 计算和子边扫描 |
| 网络评估（根+叶） | 51.71% | 47.54% | 同上，包含编码、传输、GPU 运算与等候，不是纯 GPU 时间 |

第一套探针的网络评估占比为 51.64%/41.95%，与第二套存在差异；不把一个窗口中的等待比例当常数。
第一套计时相对无计时的 8-worker 合计组墙钟差 +0.59%，只有两轮配对。
第二套普通组墙钟合计 5.0699 -> 5.0925s（+0.44%），强组 20.9870 -> 20.8614s（-0.60%），四轮交替顺序。
负扰动估计反映测量噪声，不表示插桩加速，也不能证明计时完全无开销。

第二套按局面阶段分组的动作边扩展占比：开局 9.98%/11.06%、中局 12.57%/12.11%、残局 8.02%/7.26%。
选子占比：开局 2.67%/3.37%、中局 3.28%/4.83%、残局 3.86%/5.43%。
旧报告约 33% 的扩展成本来自旧模型、未启用 lazy/合法着编译的组合，不能当作本次或生产占比。
本次 11% 的计时边界也不包含 lazy 的完整分布准备，不能把差值单独归因于 lazy。

## cProfile 候选排序

cProfile 相对串行无计时平均耗时增加 58.52%/75.91%；只用于寻找函数与重复工作，不当生产成本或加速率。
下表累计时间包含子调用，不可相加；百分比的分母是该预算下 cProfile 自身记录的总时间。

| 函数 | 800 调用数 / 累计占比 | 3200 调用数 / 累计占比 | 说明 |
|---|---:|---:|---|
| `_full_chance_outcomes` | 163,299 / 8.03% | 656,379 / 7.05% | 包含 `sample_reveal_outcomes`；展开与导航重复构造完整边际分布 |
| `_chance_specs` | 12,974 / 4.25% | 51,535 / 4.13% | 对每个动作构造字典、查询计数和求和；在扩展计时之外 |
| `GameState.apply_move` | 30,701 / 5.24% | 171,519 / 5.77% | 包含 Undo 构造、长将/长捉、局面键和重复计数更新 |
| `BeliefModel.info_state` | 30,719 / 2.60% | 171,537 / 2.60% | 棋盘、池、规则字段、完整重复历史字典快照 |
| `InformationState.determinize` | 14,400 / 3.10% | 57,600 / 2.49% | 每个模拟重新生成世界；包含未知移除采样和 GameState 构造 |
| `BeliefModel.for_simulation` | 14,400 / 1.28% | 57,600 / 1.29% | 双方模拟观测账本构造 |
| `information_set_key` | 30,719 / 0.66% | 171,537 / 0.91% | 完整公开/私有路径与行动者状态的不可变键 |

源码检查确认 `apply_move` 已经原地更新模拟棋盘；不是每走一步 clone 整个 GameState。
真正的重复工作之一是 `azero.py` 搜索循环每走一层执行 `info_state`，随后通常只用它生成信息集键。
完整独立信息态主要在叶输入与机会规格准备时才需要，中间层可以研究直接从模拟状态和行动者账本生成同一个键。
这里的结构观察不等于该优化已通过验收。

## 建议顺序与未验证假设

| 顺序 | 候选 | 依据与未知项 | 主要风险 |
|---|---|---|---|
| 0 | 下次启动续训时启用已有合法着 Cython | 历史 32 对完整局平均配对省时 3.10%；当前最新生产仍未开，未重测本模型的整轮收益 | 有效二进制和来源身份须确认；不热切换 |
| 1 | 完整机会分布/规格的小范围准备复用 | 当前反复生成相同短分布；先测本地重复率及构造/查表成本，再考虑仅限 search/节点的不可变小表 | 不缓存世界抽样、不改变完整支持、概率运算或 RNG；不扩展到 k>0 随机子集 |
| 2 | 中间层直接构造信息集键，叶上才保存完整信息态 | 可减少中间层列表、字典和 dataclass 分配；预计收益有限，尚无 A/B 数据 | 保留全部键字段与私有信息隔离；叶输入快照不可被下一次模拟覆盖 |
| 3 | 规则更新中的整数热点精确编译 | `_checker_squares`、`_piece_threat_targets`、长将/长捉维护可研究局部 typed 循环；apply 更新不是最大项 | 同码棋子身份、目标并列、异常/回退及 apply/undo 必须完全一致 |
| 4 | 编码或 PUCT 扫描继续原生化 | 有实测边界成本；先提取小范围循环，现有对象只套 Cython 的节点实验收益不足 | 编码值逐位一致；PUCT 浮点顺序、同分优先级、整数范围不变，禁止 fast-math/FMA 重排 |

顺序 1 是 CPU 侧纯函数准备数据的复用，不是跨批次神经网络输出缓存，不共享节点统计，也不是图搜索。
上述顺序是工程判断；新方案的查表收益、编译收益和完整局收益都未证明。
不承诺单项微测倍数可变成整轮倍数；完整局仍受 GPU 等候、机器状态和强局长尾影响。
不优先重写全部棋盘/节点表示，也不继续仅把 Python 对象构造器放进 Cython：既有节点初始化长测更慢。

## 验收与未覆盖项

- 首套 36 个局面/预算条件的原始、cProfile、边界计时及重复搜索保持策略、选着、搜索 RNG、叶计数和机会计数相同；各次搜索输入状态/信念/历史摘要不变。
- 首套 8-worker 两轮共 72 对原始/边界搜索相同；第二套四轮存储 288 次搜索，全部与首套参考精确相同。
- 相同后端组合的定向回归 `python -m pytest -q test_profile_selfplay.py`：**8 passed / 6.29s**；没有生产代码改动，不重跑全量训练/棋力验收。
- 下一项优化需额外验证完整网络输入/输出流、规则/信念状态、动作顺序和整局样本摘要，不能只靠本次策略/RNG检查。
- 必须保持模拟预算、网络批次/顺序、精度、浮点归约顺序、长将/长捉/重复/无吃子历史、完整机会支持及行动者信息隔离。
- 当前没有候选实现或新的加速 A/B；没有 1024 局混合预算稳态、连续 CPU 频率/温度、调度/GC、完整 4M 内存峰值、父进程样本 IPC/增强/压缩的分项测量。
- 本次不是棋力或训练收敛实验，不以热点占比推断数据效率；FP16后续降优先级，主线精度不变。
