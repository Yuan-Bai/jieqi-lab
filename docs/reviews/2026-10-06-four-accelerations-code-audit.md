## F1 [P2] 机会分配基准强制依赖未启用的固定节点二进制

该工具要求攻击/合法着后端为 Cython、节点后端为 Python，却在保护清单中无条件加入
`ROOT / "_jieqi_search.cp311-win_amd64.pyd"`。随后对全部路径执行 `file_record`，不存在时直接抛出
`FileNotFoundError`，尚未加载模型或开始计时。

用户按当前推荐配置只构建攻击与合法着两个模块时，四项训练加速可以正常使用，这个基准却不能运行。
节点编译是独立可选实验，不应成为按需对象分配验收的必需依赖；固定文件名还绑定 Python 3.11/Windows，
无法覆盖其他 ABI 或 `.so` 文件。

隔离复现已通过：复制保护清单所需源码到新目录，保留实际有效的攻击/合法着加载身份，
节点后端保持 Python，省略未使用的节点二进制，调用原 `main`。它在预检哈希阶段抛出上述异常；
没有创建 benchmark JSON/JSONL，没有启动性能测试，也没有移动或删除本机现有二进制。

建议：不强制加入该固定路径；如果需要保护未启用的可选产物，仅对实际存在的文件记录哈希。
实际使用的攻击/合法着二进制仍必须由 `*_BACKEND_NATIVE["path"]` 记录并校验。
增加“没有节点扩展仍能通过预检”的回归。此次只记录，不修改实现。
