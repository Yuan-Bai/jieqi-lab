## 中断现场与修复

用户 traceback 在 spawn 导入主模块/torch 阶段，尚未到 worker initializer；旧 SIGINT 忽略设置太晚。现场核对主进程 PID 15516 的命令行、工作目录、创建时间和后代关系，仅结束该训练及七个 Python worker；检查点/latest/状态哈希未变。

同机制隔离复现：隐藏独立控制台中，worker 在 torch 导入阶段暂停，父进程传输 32 MiB 参数。Ctrl+C 导致 worker KeyboardInterrupt，而父进程卡在 spawn 写入，超过 3s 仍未退出。原 Python 信号处理器无法在此阻塞窗口执行。证据：`data/pilots/interrupt_20261002_d99d6a35/before_enabled/`。

修复设计见 [ADR-0017](../adr/0017-windows-training-interrupt.md)：提前处理 worker 信号，Windows CLI 建立只属于本次训练的 Job Object，原生控制台回调终止此组，绕开主线程、stdio 和 executor 锁。

- 启动阻塞复现修复后约 **0.28s** 退出，退出码130，无 worker 残留或 traceback。
- worker 运行中和 stderr 阻塞的 Ctrl+C 探针约 **0.28–0.30s** 退出；Ctrl+Break、外部停止父进程的后代清理集成测试通过。
- 新增12项回归，专项组合 **47 passed**；全量 **220 passed（50.71s）**，CLI help、编译/diff 检查通过。
- 基线、探针、日志汇总位于 `data/pilots/interrupt_20261002_d99d6a35/`；已核对的训练目录及旧模型目录产物哈希未变。
