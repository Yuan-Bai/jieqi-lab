# ADR-0021：冻结对手池与模型晋升分离

- 状态：已接受
- 日期：2026-10-22
- 依据：[340局实测](../reviews/2026-10-22-opponent-pool-evaluation.md)
- 取代：ADR-0001/0005/0007 中将 RIS 阈值作为当前强度验收、按 RIS 最高分更新 best 的规定；历史验收记录保留。

## 背景

训练内 RIS-800 得分已饱和至95%–98%，当前模型对三个冻结历史模型的100局得分为
52%、49.5%、58%，各配对区间均包含50%。Pika两档各20局得分15%、5%，是更难的
外部挑战。数据不足以晋升当前模型，也不足以按历史单对手分数判断全面进步。

## 决策

1. 日常以冻结历史池为主指标；清单固定规则版本、模型哈希和搜索预算。分别记录每个对手，
   不将相关结果混成一个用于晋升的平均分。RIS保留回归，Pika用于较低频独立挑战。
2. `azero.py --eval-pool` 复用独立评估协议v2与统计v2：同洗牌换色、独立双方/环境随机流，
   整对剔除未终局，整对bootstrap区间、五类配对计数与退化提示。每个对手各跑指定局数。
   用户后续指定日常基准为双方1600模拟/叶批16，另建 `eval_pool_20261022_1600_leaf16.json`；
   旧800/64清单及实测保留，不直接拼接曲线。清单可固定search预算，运行参数不符即拒绝。
3. 默认只报告，不自动改变 `best.pt`/历史 `best_score`；最新模型继续自博弈。
   `--legacy-ris-best` 显式兼容旧单RIS最高分导出，不能与池合用。旧文件不改名或删除，
   旧已提交检查点的导出修复语义不变。新目录可能只有 latest，没有 best。
4. 历史池单独保存网络副本和训练RNG；评估不能改变后续优化/采样状态。清单在训练前校验，
   每次重验权重和清单。逐局输出和训练attempt互相引用；评估完成与训练提交是两个状态。
5. 当前没有足够证据设置自动冠军阈值；晋升另订预声明局数、留出种子和比较政策。
   不将本次已观察的探索样本当独立确认，不自动调整训练超参、训练对手混合或RIS算法。
6. 当前全量遍历三个手动冻结对手，没有自动抽样/替换。长期锚点iter19/iter34保留，
   近期参照暂为原RIS最高分iter50；确认新的候选后，冻结新文件并创建新id清单，旧文件保留。

## 后果与验证

三个历史对手使每次评估局数从100增加为300。池权重不在Git内，迁移须携带。
固定日常种子有利于跟踪，但反复调参可能对该集合过拟合，正式验收需留出。
历史池评估搜索固定为独立工具基线，训练搜索参数不全部继承，详见[操作说明](../evaluation.md)。
Pika内部历史规则与项目裁判仍有差异，保留适配范围，不能把节点数等同于AZ模拟数。

验证覆盖源文件/权重变化拒绝、真实优化的有无评估权重/RNG等价、异常恢复、
未提交评估重试保留、RIS默认只报告及旧best导出修复。没有启动生产训练或自动晋升。
最终专项141项通过；真实模型双进程限步冒烟通过，原生产四文件与四个冻结模型哈希不变。
