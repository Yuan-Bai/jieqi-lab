# ADR-0005：训练路线与 Gate（自博弈先行，蒸馏备选）

> 2026-10-22更新：按RIS最高分更新best已改为默认只报告，可选冻结历史池；旧行为需显式兼容开关。Pika已可作独立评估对手。以[ADR-0021](0021-opponent-pool-and-selection.md)为准，以下Gate保留历史上下文。

> 2026-10-03勘误：下文“噪声不进策略目标”的表述过强。本项目缺少配套forced playouts；当前仅有有界启发式裁剪，不能精确还原无噪搜索目标，见 [ADR-0020](0020-algorithm-audit-followup.md)。

- 状态：已接受
- 日期：2026-09-11
- 相关：需求访谈 Q5 / Q7 / Q9

## 背景

本机自博弈产能（优化后约 1 万局/天量级）与 AlphaZero 类方法的公开规模（数百万至数千万局）差 2–3 个数量级。揭棋论文（arXiv:2112.02989）结论"AlphaZero 不能直接用于暗中国象棋"，主要障碍是隐藏信息下的搜索目标质量与样本效率。

## 决策

1. **自博弈先行**：修复规则、归档旧数据后从零训练，Phase 1 目标累计 **2–5 万局**（Gate）。
2. **Gate 判据**：快评（50 局 @400 vs RIS-400）胜率曲线显著上升、对随机基线 >90%、loss 趋势正常。不做晋升门控，`latest.pt` 持续自博弈；`best.pt` 按配对评估分更新。
3. **训练卫生（已实施）**：
   - policy target pruning：根节点 Dirichlet 噪声不进策略目标（KataGo 技术）；
   - `train_epochs`（默认 1.0 epoch/迭代）替代固定 `train_steps=2000`，避免小数据多轮过拟合；**该项已被 ADR-0010 取代**（1M buffer 下该折算每轮仅约 15 步，Gate 训练不足）；
   - 批量叶评估 + 虚拟损失（`leaf_batch_size=64`、`virtual_loss=3.0`，可退回 `leaf_batch_size=1`）。
4. **Gate 不过则转蒸馏**：教师候选 Pikafish `jieqi` 分支（需自行构建，GPL-3：仅作数据/对手，不复制源码）或自研 C++ 深 RIS；生成监督数据后预训练 + 自博弈微调。Pikafish 构建与 FEN/UCI 桥接安排在 Stage 2，不阻塞 Stage 1。
5. **搜索改造优先级**（逐项 A/B：同种子、同预算、200 局）：
   1) policy target pruning（已完成）；2) 批量叶评估+虚拟损失（已完成）；3) 暗子机会节点（K=4 加权采样起步，可开关）；4) Gumbel 根搜索（仅在 3) 后仍不足时）。

## 后果

- 叶并行 + 虚拟损失会改变搜索统计，与 `batch=1` 非严格等价；质量差异在 Gate 阶段用快评曲线验证。
- 任何搜索改动必须带开关键，且不得破坏可复现性（固定种子）。
