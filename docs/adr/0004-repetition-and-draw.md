# ADR-0004：重复局面与无吃子和棋

- 状态：已接受
- 日期：2026-09-11
- 相关：需求访谈 Q10；天天象棋官方规则

## 背景

旧实现把 `(side, board, pool)` 全量作为重复键，暗池（隐藏信息）参与判重，导致"公开局面相同但暗池认知不同"时行为不稳定；且重复达到 4 次判负而非判和。平台规则：重复局面判和，无吃子 40 回合判和。

## 决策

1. **重复键 = 公共局面**：`(side_to_move, board)`，不含 `pool`。第 3 次出现判和（`reason=repetition`）。
2. **与禁着的关系**：若任一方长将/长捉计数 `>= 2`，暂缓触发重复判和，让禁着机制收尾（避免用重复"逃过"禁着意图）；否则立即判和。
3. **无吃子和棋**：连续 80 ply（40 回合）无吃子判和（`no_capture_plies`），可配置。
4. **legacy 行为**（仅测试）：重复 4 次判负、无吃子 50 ply，由 `RulesConfig` 预设控制。
5. `fast_outcome()` 同步实现廉价版本（王缺失→将死；legacy 分支；重复同条件；无吃子），用于自博弈快速终局判断。

## 后果

- 训练数据中的和棋原因分布需按新语义解读。
- 若后续平台规则变化，仅需修改 `RulesConfig` 与 `RULESET_VERSION`。
