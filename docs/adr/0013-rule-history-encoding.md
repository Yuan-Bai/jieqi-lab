# ADR-0013：补全公开规则历史编码并兼容旧训练产物

- 状态：已实施并验证（2026-10-01）
- 相关：算法审查 D；ADR-0012；`test_rule_history_encoding.py`
- 版本：`STATE_CHANNELS=238`、`DATA_VERSION=3`；`RULESET_VERSION=3` 不变

## 问题与反例

旧编码保存当前重复次数和最近八步，却不保存其他公开局面的次数。当前棋盘相同、当前计数相同的两个信息态，走同一步可能分别继续对局和触发第三次重复和棋，但网络输入相同。`check_anchor` 和 `chase_target_code` 虽已保存在样本中，也没有进入编码；前者决定是否同一枚棋子续将，后者决定逃离旧格的目标是否续捉。

新增回归分别验证 `[禁着, 合法]` 的将军锚点/长捉目标码反例，以及 `[未结束, 和棋]` 的其他局面计数反例。编码现在均能区分它们，叶评估去重签名同步包含完整相关历史及完整性状态。

## 历史表示与容量

保留旧 0～70 通道；追加：

| 通道 | 内容 |
|---|---|
| 71～72 | 将军发起子所在格，红/黑 |
| 73～74 | 追击目标的公共棋子码 / 31，红/黑 |
| 75 | 完整重复历史标记；缺失历史为 0 |
| 76～237 | 最多 81 个仍可能重复的公共局面，每个两通道 |

每个历史槽保存公共棋盘码 / 31，以及常量平面 `(2 * count + side) / 7`。计数和轮次可唯一还原，空槽为零；计数没有截断。棋盘码包含公开明子类型、暗子假类型及颜色，不包含暗子真实类型或私有捕获类型。采用标量棋盘码，避免每个历史棋盘都展开成 28 个独热通道。

历史键按字典首次出现顺序保存。更多棋子或更多暗子的旧局面因吃子/翻明不可逆而不可能重现，安全剔除；仍可能出现的键均保留。在默认规则下，距上次吃子至终局最多 80 ply，所以最多 81 个键。自定义长对局规则或手造历史超容量时显式抛错，禁止静默裁剪后宣称完整。该界限针对正常按终局停止的对局。

样本新增 `repetition_history: bytes | None`，每个记录含轮次、原始计数和 90 格公共棋盘码，再用 zlib 压缩。该字节记录贯穿 RawSample、标注、序列化、读取、张量还原及两种数据增强。空间变换作用于所有历史棋盘，翻面同时交换轮次及颜色，保留记录顺序。

这补全的是默认规则的公开判定历史，不是完整的策略条件信念或私有事件历史。网络仍可能学不好重复键匹配；信息完整并不保证学会规则。

## 兼容策略

- 64/71 通道模型自动把首层新增输入权重补零，旧通道和其他参数原样加载；自博弈、内部评估和工具评估 worker 也统一使用该加载函数。更大输入或其他结构不匹配仍报错。
- 读取 v2 与 v3 数据。真正的 v2 slots pickle 没有新字段，加载后补 `None`；保留当前重复计数与已有锚点/目标码，完整性平面及历史槽填零。不能从八步历史伪造完整的重复表。
- 旧 v1 和未知版本继续拒绝；规则版本校验不变。v3 文件允许含历史缺失的旧样本，例如合并产物，缺失标记仍保留。
- 不重置训练状态、不归档或覆盖既有模型/样本。用户的 batch=1024、buffer=4M 保持原值。旧搜索目标与缺失历史只能随新样本逐步替换。

首层补零保持数学上的初始前向等价；CUDA 通道尺寸变化会选择不同的 cuDNN/TF32 内核，不能承诺默认 GPU 输出逐位一致。当前真实模型批量验证：完整 FP32 输出最大差为 0；默认 TF32 最大策略概率差约 0.000449、value 差约 0.00245。没有据此宣称棋力不变或变强。

## 验证与成本

- 全量 **167 passed in 31.23s**；新增 8 项规则/去重/完整历史往返/增强/容量/旧数据与旧模型兼容回归。
- `audit_information_probe` 的将军锚点和其他局面重复反例均已转为不同输入；私有捕获观测边界回归保持通过。
- 随机 10 局 **1,559** 个非终局信息态，张量还原及双重镜像/翻面还原均一致；最大相关历史 30 个键，压缩历史平均 110.5 bytes、最大 386 bytes。
- 翻面 lockstep 20 局 **2,803 ply**，合法着法/胜负零差异；12 ply 的原有 chase 扫描次序记账近似未放大，不能宣称规则字段全部逐位一致。
- 真实 71 通道 `latest.pt` 加载成功，执行一次实际 `train_step`（仅内存，不保存），损失/梯度有限，新增通道梯度非零。真实 v2 文件 62,088 样本可读取，其重复历史均标为缺失；抽取 16 个做四向增强及张量验证通过。
- 实际模型 off/on 各一局，@64 sims、30 ply，搜索走后自将均 **0/1,920**，实际走子均为 0；仅运行检查，不是棋力评估。
- RTX 4060 Laptop、FP32 输入、batch=64 的单次微基准：71 通道约 3.98 ms，238 通道约 4.19 ms（约 +5%）。该数字只测网络前向，不代表整体训练/搜索开销。
- 首层新增 96,192 参数（约 1% 的现有网络）。batch=1024 的 FP32 输入本身增加约 58.7 MiB；缓冲还增加压缩字节对象及引用，4M 样本按上述平均仅字节内容约 422 MiB，另有 Python 对象开销。后续应测完整训练吞吐和峰值内存。
