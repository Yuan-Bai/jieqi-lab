## 背景

存在一份未完成的 C++ 端口（规则 + RIS-ISMCTS + OpenMP + Qt GUI，归档于 `<LOCAL_WORKSPACE>/jieqi-cpp-prototype.7z（历史归档，未随源码分发）`）。C++ 在搜索提速与多线程对弈上有明显价值，但维护双实现有规则漂移风险，且本机目前只有 VS2022 + Anaconda Qt，尚无验证过的构建链路。

## 决策

1. **Python 保持权威**：规则语义、训练、评估协议以 Python 实现为准。
2. **C++ 定位为后端**（Stage 2 启用）：高迭代对弈、评估对手、数据生成；不承载训练。
3. **Stage 1 仅做编译验证**（≤半天）：解包到独立目录，验证能否用 VS2022/Anaconda-Qt 构建并跑通 `ismcts` 基准；输出可行性报告，不投入功能开发。
4. **规则同步机制**：conformance 测试向量——FEN 局面回放 + perft/合法着法对比 + 随机对局回放；C++ 改动必须通过同一套向量。Python 侧 FEN 导入导出已就绪（chessprogramming.org/Jeiqi 规范）。
5. **退化选项**：若双实现维护成本过高，C++ 版冻结为"仅对弈客户端"或放弃。

## 后果

- 不阻塞主线的任何交付；S1.7 产出仅为可行性结论。
- 若启用，需在 CI/本地脚本中固化 conformance 流程。
