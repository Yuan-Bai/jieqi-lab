# ADR-0014：完整世界抽样与机会分支按需补建

- 状态：已实施并验证（2026-10-01）
- 相关：算法审查 E；ADR-0012/0013
- 实现：`NeuralMCTS._navigate_chance`、`PUCTNode.expand`、`sample_reveal_outcomes`
- 版本不变：238 通道、`DATA_VERSION=3`、`RULESET_VERSION=3`

> 上述版本与预建默认值是 2026-10-01 的实施记录。当前规则 v5；2026-10-06 已将 on/k=0 对象按需分配设为默认，见文末和 [当前加速配置](../performance.md)。

## 已确认的问题

旧 `chance_k>0` 在展开时固定少量揭示类型，导航只在这些类型中按世界计数重新归一化。设世界计数为 c、保留集合为 C，旧采样实际是：

`P_old(t | world,C) = c[t] * I(t in C) / sum(c[u] for u in C)`

所需分布则是完整暗池上的 `c[t] / sum(c)`。例如仅缓存兵，而世界车:兵=9:1 时，旧导航会永远选兵。若缓存与世界完全不相交，旧代码改用自然抽样兜底；部分相交时却持续偏采，没有补救。

即使把初始缓存的随机选择也取平均，仍有偏差：权重 `[5,3,2]`、k=2 的旧无放回预选+子集归一化，整体概率为 `[0.553571,0.289286,0.157143]`，不等于 `[0.5,0.3,0.2]`。本次用穷举验证该反例，并把实际导航的断言改为正确分布。

## 修复

每条模拟先根据当前公共棋盘判断是否存在移动揭示与捕获揭示，然后从对应**完整模拟世界暗池**抽取类型。再查找或补建节点，使用同一次抽取结果应用着法。缓存缺失不重新抽样、不退回条件于缓存的分布。

- 暗子移动：完整移动方池抽一次；明子移动不抽移动类型。
- 吃暗子：完整被吃方池抽一次。合法着法的双方颜色不同，两次抽取使用各自的池，得到正确的世界条件联合分布。
- 单揭示补结果节点；双揭示可补移动结果层及其捕获结果节点。已有结果复用，正常接入信息集决策图及路径回传，不修改价值权重。
- 新节点与同层节点保持相同行动方，虚拟损失按原路径添加和回收。私有捕获结果仍按被吃方的可见信息共享决策，不能拆分其策略。
- 正常缓存遗漏不会触发 `chance_nav_miss`；无有效池或公共节点结构不一致仍保留异常兜底。新增 `chance_outcomes_added` 记录动态补建的环境节点数量。

因此，对任意初始缓存 C，当前模拟的 `P(t | world,C)` 都等于完整池概率。给定固定的结果价值时，均值回传使用普通 Monte Carlo 样本即可，无需逆概率加权。

这只修复环境抽样的支持偏差，不保证有限预算 PUCT 的最终 Q 无偏，也不补全行动者的策略条件后验或提供均衡收敛保证。

## k 与先验的新含义

`chance_k=0` 继续全量预建；`k>0` **只限制每层初始预建的类型数量**，后续补建可使数量超过 k。单层最多六种棋子类型；双揭示最多六个移动层、各六个捕获结果，不是严格的全树内存上限。

`sample_reveal_outcomes` 保留预建分支在完整信念中的原始概率，子集概率和可能小于 1；遗漏质量不分摊给已有结果。入口机会节点保存完整计数的不可变快照，为新分支设置一致的边际先验。实际导航只用当前世界计数，不用这些先验。

`PUCTNode.sample_outcome` 是辅助工具：按已建分支先验归一化。缓存未完整时，它只表示条件于缓存的分布，不能用作搜索环境采样器。训练/评估 CLI 帮助及日志已同步更新。

旧模型、v2/v3 样本仍按 ADR-0013 的方式加载；本次没有改编码或持久化字段。旧 k4 实验臂的名字可以保留，但其搜索语义已改变，不能用新代码复现旧截断行为或把旧结果当作新采样器的收益。已有 A/B 产物与完成标记未修改。

## 成本与后续

按需补建可以减少未访问分支的预分配，但不承诺节点数始终 ≤k 或必然更快。实际访问的类型增多后，缓存会增长；完整计数快照及新增节点槽也有内存成本。继续默认 k=0，先测完整训练吞吐/峰值内存，再决定是否更改预建策略。策略条件后验与完整私有历史属于后续算法工作，不能作为本次已解决项。

## 2026-10-06：k=0 对象分配实验

新增默认关闭的 `--lazy-chance-allocation`，只允许 `chance_nodes=True, chance_k=0`。
它与上面的 k>0 预建子集不同：保留完整逻辑支持和原始枚举序号，只在实际世界抽到结果时分配对象。
所有动作边仍在扩展时创建，先验归一化复用当前 Python/Cython 实现；不会改变网络批次或信息集共享方式。

世界抽样仍先移动揭示、后捕获揭示，各抽一次。新增对象使用不可变计数快照算出原 k=0 的边际先验，
访问统计、虚拟损失、回传符号不变；延迟分配完整支持中的对象不计入原来的 `chance_outcomes_added`。
遇到与计数快照不一致的外部状态时，先补全原始布局，再走既有防御路径。

`materialize_chance_outcomes` 可无 RNG 地恢复 eager 布局，并保留已访问节点和共享引用。
辅助 `sample_outcome` 在该实验模式下先补全整层，避免把当前已分配结果误当完整边际分布；
k>0 辅助采样的原含义不变。训练搜索不调用辅助补全方法。

物理树、节点个数及未补全树的序列化会不同；补全后的完整逻辑图、网络输入输出、
策略、走法、RNG 和训练样本才是等价性判据。测量与启用结论见
[对象分配验证报告](../reviews/2026-10-06-lazy-chance-allocation.md)。
本次不修改规则、编码、数据或搜索版本，也不实现网络缓存、图搜索或策略条件后验。

## 2026-10-06：按需对象分配成为默认

经完整输入/输出/逻辑图、策略、样本与 RNG 精确对照及 64 局吞吐测量后，
用户选择将该对象分配优化设为 on/k=0 的默认行为。实现不变，只调整配置解析、CLI 回退与日志。

- `AZConfig` 省略分配字段或传 `None` 时，按机会配置解析为 bool：on/k=0 为 True，off/k>0 为 False。
- CLI 未显式指定分配开关时也按最终机会配置选择，不使旧 off/k>0 命令失效。
- `--no-lazy-chance-allocation` 显式恢复 k=0 全量预建；显式 True 与不兼容机会配置仍拒绝。
- 旧完整检查点保存 False 或缺少该字段不阻止当前 v5 完整续训；恢复不会覆盖新 CLI 配置，不重置优化器或缓冲。
- 默认路径、显式开启与原全量路径比较完整输入、逻辑图、策略和 RNG；续训回归核对模型、优化器、调度、计数、缓冲和文件不改写。

版本不变：`RULESET_VERSION=5, DATA_VERSION=3, SEARCH_VERSION=3`。
原始测量保留不重写，当前配置统一见 [performance](../performance.md)。
