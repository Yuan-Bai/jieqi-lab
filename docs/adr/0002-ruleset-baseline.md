# ADR-0002：规则基准与版本

- 状态：已接受（2026-09-11 修订：版本由 2 升至 3，见 ADR-0009）
- 日期：2026-09-11
- 相关：需求访谈 Q2 / Q10；研究文档 `docs/research_jieqi_azero.md`

## 背景

揭棋规则在不同平台存在差异（被吃暗子是否公开、明士象能否过河、无吃子和棋步数、重复是否判和等）。旧实现（`RULESET_LEGACY`）存在多项与主流平台不一致之处，且有一个已复现的判定顺序缺陷：`game_outcome` 先判长将后判将死，导致"将死时若连将计数超限"会错误判负。

## 决策

1. **基准规则 = 天天象棋官方揭棋规则**，以此为准；Pikafish `jieqi` 分支作为交叉验证参考（其 FEN 规范用于导入导出）。
2. **`RULESET_VERSION = 3`**：规则语义版本号，写入训练状态与自博弈数据元信息；版本不匹配的数据/模型不加载。版本历史：0 = legacy，1 = 中间开发版（未发布），2 = 天天象棋基准（首版），3 = 修正马腿判定与按子长将/长捉（ADR-0009）。
3. **判定顺序修正**：将死/困毙优先于长将/长捉与重复；之后依次为禁着判负、重复判和、无吃子和棋。
4. **规则可配置**：`RulesConfig`（frozen dataclass）承载全部规则参数，内置预设：
   - `RULESET_TIANTIAN`（默认，version=3）：6 回合禁着、重复 3 次判和、无吃子 80 ply；
   - `RULESET_LEGACY`（version=0，仅供回归测试）：即时长将判负、重复 4 次判负、无吃子 50 ply、不做禁着。
5. **对齐要点**（与旧实现差异）：
   - 暗象受河界限制、暗士限九宫（明士/象无区域限制）——与平台一致；
   - 被吃暗子仅吃方知类型，原主不知（暗池按观测递减）；
   - 长将/长捉为禁着而非即时判负（见 ADR-0003）；
   - 重复按公共局面键判和（见 ADR-0004）。

## 后果

- 旧版训练数据/模型与新规则不兼容：v0 已归档至 `data/legacy_20260911/`；v2（384 局）已归档至 `data/legacy_ruleset_v2_20260911/`，训练从零开始。
- 规则任何语义修改必须升 `RULESET_VERSION` 并同步 ADR 与测试。
