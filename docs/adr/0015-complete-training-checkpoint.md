# ADR-0015：轮次提交点与完整训练检查点

- 状态：已实现并验证（2026-10-01）
- 实现：`azero.py`、`test_training_checkpoint.py`
- 关联：[当前状态](../status.md)、[训练预算](../reviews/2026-10-01-training-budget.md)、[缓冲回填](../issues/0006-resume-load-incomplete-buffer.md)

## 问题

之前只保存 `latest.pt` 和 `train_state.json`，恢复时重新创建 AdamW，按轮数快进 cosine。优化器动量及 RNG 丢失；权重与 JSON 分开更新，可能因中断属于不同轮次。

自博弈数据在优化前就写出，失败轮次的文件会在重启扫描目录时混入缓冲。连续训练按每局增强，而旧加载器按整文件增强，导致 FIFO 顺序甚至容量裁剪后的样本集合不同。多进程返回的完成顺序也会改变抽样索引。

## 决策

1. 增加 `models/training_checkpoint.pt`，格式 `jieqi-training`、schema version=1。保存模型、AdamW、scheduler、TrainingState、全局 Python/NumPy/Torch/CUDA RNG、训练循环独立 RNG、架构、完整配置及规则/数据/搜索版本。当前 `SEARCH_VERSION=1`，搜索语义改变时递增。
2. 完成优化/评估、推进 scheduler 和已完成轮计数后，通过同目录独立临时文件、flush/fsync、原子替换提交单文件。这是续训的提交依据。写入或替换失败，旧检查点保留。
3. `latest.pt`/`best.pt` 仍为纯权重，JSON 仍为原 TrainingState 格式；GUI、评估和已有工具继续使用它们。提交完整检查点后才导出；恢复时以检查点修复可能滞后的 latest/JSON。若该提交刚更新 best，也恢复其 best 导出。
4. 首次训练或从旧纯权重迁移时，生成新数据前建立轮前检查点。以后即使第一轮中断，也能恢复到该提交点；不会把未提交数据自动混入。
5. 检查点保存重建当前 FIFO 所需的文件清单、顺序、SHA-256 和增强样本数，以及实际缓冲大小。只读取清单文件；不扫描混入目录中的孤立/外部文件。所需数据缺失、被修改或版本错误，显式拒绝完整续训。
6. 新数据记录 `game_lengths`。回填时按生成时的每局顺序增强；老文件无边界信息时保留整文件增强语义，迁移后对重建的缓冲建立提交点。worker 结果按提交任务索引汇总，完成时序不决定缓冲顺序。重启同一轮的文件名发生碰撞时另存，保留原文件。
7. 损坏/不兼容的完整检查点不静默降级到纯权重。缓冲容量或增强开关改变，初始实现要求新目录热启动；2026-10-19 增加显式扩容迁移，见下文。缩容或改变增强仍需新目录热启动；纯权重仍允许 64/71 通道补零加载。旧优化器/RNG 无法从权重补回，日志明确提示兼容续训。
8. 完整恢复默认要求优化器/LR 配置一致；cosine 的 `iterations` 也是调度配置。改变 LR、调度、weight decay 或 cosine 总轮数时，必须显式 `--reset-optimizer`，重建 AdamW 和 scheduler，再按当前轮数快进。模型、计数、缓冲与 RNG 保留，但不再称为完整优化状态续训。搜索/其他运行配置可改变并记录告警。

## 使用与迁移

保留原运行命令即可恢复；完整检查点存在时优先使用它，旧 JSON 或 latest 不能覆盖它的轮计数。`--max-load-files` 只用于无完整检查点的兼容回填；完整恢复使用保存的清单。

迁移机器时保留模型目录和检查点引用的自博弈文件，放在新 `data_dir/selfplay`，保留文件名与内容。检查点只存清单，不存整个 4M 缓冲；不能单独搬一个检查点就完整恢复。历史 best 模型也应保留，其权重不总是当前 latest。

以后改变优化设置时，例如在原运行命令中将 LR 改为 `--lr 2e-5` 并追加 `--reset-optimizer`；其余参数保留。本次不执行长训命令。

用户主线仍为旧产物（iteration=269、71 输入通道），本次没有在主线运行迁移或训练。以后第一次使用新入口训练才建立完整检查点；过去未保存的动量/RNG 无法追溯。

## 验证与代价

- 新增 18 项测试：真实 CPU/CUDA AdamW 更新与 BN/dropout/RNG 恢复，训练循环连续/重启等价，跨文件 FIFO 部分裁剪、目录孤立文件、文件内容校验、首轮优化失败、完整提交后导出失败修复、写入/替换失败、版本与配置拒绝、旧纯权重兼容、worker 完成顺序、提交状态一致性。
- 全量回归：`python -m pytest -q` → **191 passed（31.49s）**。
- 固定小数据的连续两段优化与保存/恢复后的两段优化，模型、AdamW、scheduler 和 RNG 逐元素一致。训练循环测试使用轻量网络和固定自博弈结果，验证提交路径，不测试长时间棋力。
- 真实主线权重另存于 `data/pilots/checkpoint_20261001_67da096d/` 做 CUDA 微测：934 万参数，270 原始/1,080 增强样本，batch=8、两次更新；恢复后的第二次更新与连续路径模型最大差 **0**，AdamW/LR/RNG 一致，主线权重哈希不变。
- 该真实检查点为 112,216,928 字节（约 107 MiB），保存/恢复各约 0.13s（短时单次测量、当前硬件，小缓冲）；无完整 4M/8-worker 资源结论。AdamW 两组动量使检查点约为纯权重三倍，纯权重导出额外保留。
- 保存的是轮次边界；轮中中断后重新执行未提交轮次。文件仍保留，评估日志可能已有未提交轮的记录；后续已实现的 [ADR-0016](0016-run-provenance.md) 用独立 run/attempt ID 与提交标记追踪新记录。
- 不承诺跨硬件、跨库或未约束的 GPU 内核逐位复现；已保存 RNG 与有序任务汇总减少可避免的差异。CUDA 设备数改变时明确告警。

2026-10-11 更新：完整续训增加入口及逐文件恢复进度；FIFO 改为原地裁剪，回填按有界批次插入，重建期间暂停自动循环 GC 并在退出时恢复。恢复顺序与检查点格式保持不变。当前 4M buffer 单次实测 329.4s → 202.3s，定向回归 137 passed；测量边界与状态一致性验证见[续训等待修复](../reviews/2026-10-11-resume-wait-fix.md)。

2026-10-19 更新：显式扩容续训。

- 在原命令中设置 `--replay-buffer-size 5000000 --allow-buffer-growth`，其余目录、学习率、训练步数、cosine 总轮数等参数保持原值。默认仍拒绝容量变化；开关只允许从正容量增大，不支持缩容、无完整检查点或 `--no-resume`。同容量下保留开关无副作用。扩容后再次启动须保留新容量，开关可省略；再次扩容需再次显式开启。
- 先用保存的旧容量、已提交文件清单、SHA、规则及增强计数精确恢复旧 FIFO，再提高容量。仅由后续新数据填满，不扫描历史目录，也不重新加入首文件中已淘汰的前缀。模型、AdamW、调度、轮数、RNG、固定诊断不因扩容重置；优化设置同时改变时仍另需 `--reset-optimizer`。保留 RNG 不代表扩容后的训练轨迹与原容量逐位一致。
- schema version=1 增加可选重放记录字段 `skip_augmented`，默认 0，表示在每局增强后的串接序列中跳过多少条文件前缀。`augmented_count` 仍为完整文件增强条数，用于原校验；有效条数为两者之差，用于清单淘汰和缓冲大小核对。仅扩容迁移时明确记录已有 FIFO 起点，兼容读取原检查点；原始自博弈文件及增强顺序不变。字段是恢复语义的一部分，带此字段的扩容产物应使用支持扩容的代码恢复。
- 开始新轮次前，原子提交扩容后的轮前检查点，保证第一轮中断也能按新容量正常恢复。来源 manifest 的 parent 记录 `resume_mode=buffer_growth`（同时重置优化器时为 `buffer_growth_reset_optimizer`）、旧/新容量和保留样本数；旧父检查点哈希仍可追溯。固定诊断沿用原数据集和报告，不重新划分。
- 回归覆盖部分首文件裁剪、未填满时保存/重启、再次扩容、达到容量后正常淘汰、未提交数据隔离、真实 AdamW/调度/RNG 保留、固定诊断、迁移提交失败及后续轮次中断。仅在临时目录运行测试，不迁移生产检查点、不启动主线长训；大容量的内存与棋力收益仍需单独实测。
- 验证：`python -m pytest tests/test_training_checkpoint.py tests/test_training_diagnostics.py tests/test_run_records.py tests/test_azero.py -q --tb=short` → **167 passed（45.07s）**；Python 编译及 `git diff --check` 通过。Windows 沙箱禁止来源记录的硬链接操作，最终测试在沙箱外使用系统临时目录执行；未运行全量仓库测试。
