# ADR-0018：固定整局留出与持久化训练诊断

- 状态：已实现（2026-10-02）；正式32局留出待用户下一轮续训建立
- 实现：`training_diagnostics.py`、`azero.py`、`tools/diagnose_training.py`
- 关联：[当前状态](../status.md)、[完整检查点](0015-complete-training-checkpoint.md)、[来源记录](0016-run-provenance.md)、[五轮检查](../reviews/2026-10-02-five-iterations-and-interrupt.md)

## 问题

目前已完成五轮，但缓冲和自博弈目标每轮变化。训练的策略交叉熵还包含目标熵，只看平均loss从2.873升至2.997，无法区分目标变难、过拟合或优化问题。已有五轮样本已被训练使用，不能事后改称独立留出集。

## 决策

1. `--diagnostic-games N` 首次启用时，从下一轮新生成且结束的完整对局中一次性选N局；独立固定种子20261002，按普通/高强度搜索分层。另选不重叠的N局作为固定训练参照，需要当轮生成局数至少2N。1024局、每8局强搜索、N=32时，留出与参照各含4局强搜索、28局普通搜索。
2. 留出发生在增强之前。留出原始样本单独写到 `diagnostics/sets/<attempt_id>/heldout.pkl.gz`；其镜像和翻面副本均不生成，也不进入缓冲。固定训练参照单独保存原始样本，同时按正常增强进入训练。`selfplay/` 当轮文件只含参与训练的完整对局，并记录原任务索引及排除局号。这样旧回填入口也不会误读留出样本。
3. 固定集只建立一次。后续每轮新对局全部用于训练，继续检查原固定集。当前实验旧缓冲保持训练用途，不随机分行、不追认旧数据为留出。独立数据指不同整局；常见开局和局面可以自然重合，不要求棋盘内容去重。
4. 每轮更新之前和之后，以eval模式对同一批原始目标记录策略CE、目标熵、KL（自然对数），value MSE、偏差、均值与常数基线、10个[-1,1]区间的预测/目标均值。PCR策略权重0的样本只参与value，整集无策略权重时策略指标为null。指标按局面加权，长对局权重更高；同局局面有相关性，不用样本数宣称独立统计精度。
5. 诊断不调用训练或搜索随机采样，不做梯度更新；恢复每个模块原有train/eval状态，BN统计保持不变。训练参照和留出分别推理，不影响下一次训练抽样。
6. 记录实际更新步数、抽样数 `steps * batch_size`、缓冲及新增增强样本数。本轮单个缓冲样本的期望抽样数为抽样数/缓冲数；抽样数/新增数只作为满缓冲、稳定数据率时的近似生命周期复用，不是实测逐样本计数。
7. 完整检查点新增可选 `diagnostics`，嵌入固定集来源、局号、相对路径/哈希/数量和最近一轮报告；旧schema=1检查点兼容，无该字段代表尚未建立。已有固定集自动恢复，即使省略启用参数也继续诊断；显式改变已固定的局数拒绝恢复。固定集缺失、被修改、报告与模型/轮次/attempt不一致时拒绝完整续训。
8. 每轮报告按attempt独立写到 `diagnostics/reports/<attempt_id>.json`。写报告后、完整检查点提交前仍可能中断，提交状态通过既有commit记录或当前检查点核对。只比较同一 `dataset_sha256` 的已提交报告；失败的候选集/报告保留，不在恢复时扫描采用。最新报告可从已提交检查点补回，已有不同内容的报告不覆盖。
9. `--run-iterations N` 限制本次新增轮数，不改变cosine的全程 `--iterations`；0维持原先训练到总轮数的行为。分段运行保存同一优化器、调度器、缓冲与RNG。

`RULESET_VERSION=3`、`DATA_VERSION=3`、`SEARCH_VERSION=1`及检查点schema=1保持不变。新增元数据不改变编码或搜索语义，运行源码/配置哈希记录本次训练流程变化。

## 使用与读数

正式续训命令、输出路径和检查方法见 [续训说明](../reviews/2026-10-02-fixed-diagnostics.md)。迁移机器除原检查点/自博弈文件外，还要保留引用的 `diagnostics/sets/`；报告与runs目录也建议一起保存。

策略CE = 目标熵 + KL。固定集的熵保持相同，更适合比较KL是否下降。value预测是[-1,1]的胜负结果期望；包含和棋时不能直接视为获胜概率。校准区间比较预测均值和实际结果均值，不以单个局面的输赢判定预测正确与否。

训练参照持续改善而留出连续恶化，或差距持续扩大，提示泛化问题，需要结合学习率、更新步数及数据变化进一步判断。两边都改善表示对固定目标的拟合改善，仍不等于棋力提升。只有32局，结果有噪声；对局分布随模型变化，长期固定集会逐渐成为历史分布。训练参照进入FIFO后也会被逐渐淘汰，届时它不再代表当前仍在训练的样本，不能机械地解释长期差距。

## 验证

- 新增15项回归：分层整局排除及全部增强、真实指标数学与PCR、BN/模块状态/RNG保护、旧检查点/旧配置兼容、真实AdamW分段续训等价、候选集/报告中断提交边界、缺失/修改文件拒绝、报告恢复与防覆盖、CLI限轮及参数校验。
- 全量回归：`python -m pytest -q` → **235 passed（53.28s）**。CLI帮助、只读诊断入口和Python编译检查通过。
- 独立CUDA短测：`data/pilots/diagnostics_20261002_4c18462b/` 使用真实238通道网络和既有270局面诊断素材，留出1局/29局面，参照1局/57局面；3局训练241原始/964增强样本，batch=8、2+2次更新，第二段不生成新局以避免重复插入留出素材。恢复后固定集相同、两份报告已提交，额外诊断前向约0.023s（86局面，单次短测）。
- 该短测仅验证数值与持久化路径，素材来自历史诊断、LR为默认5e-4，与用户正式5e-5/1024局预算不同；不据其loss变化判断泛化、棋力或正式32局耗时。
- 用户旧目录和五轮训练目录的模型、检查点、状态、数据与日志哈希保持一致；未启动用户续训。
