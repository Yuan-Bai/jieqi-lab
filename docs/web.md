# Jieqi Lab 网页版

## 启动

在项目根目录运行：

```powershell
python web_server.py
```

浏览器打开 [http://127.0.0.1:8765](http://127.0.0.1:8765)。更换端口：

```powershell
python web_server.py --port 8888
```

Python 3.11+ 即可运行规则、人机纯搜索和整个界面；不需要 npm、前端构建或额外 Web 框架。
AlphaZero 继续使用项目已有的 PyTorch、NumPy 和本机模型。服务默认仅绑定本机。
这是本地浏览器对弈应用；双人模式是同屏轮流走子，尚不提供远程房间、账号或匹配服务。

### Host 与同源限制

GET/POST 在处理静态文件、API 或创建会话前校验 Host。默认接受
`127.0.0.1:实际端口` 和 `localhost:实际端口`；`--port 0` 使用系统实际分配的端口。
存在 Origin 时必须与已验证的 Host 同源；跨站请求、重复 Host/Origin 和错误端口返回 403。
本地 CLI 可不带 Origin，但仍需可信 Host。

如需在可信局域网使用，显式绑定本机的具体网卡地址，例如
`python web_server.py --host 192.168.1.10`，然后通过该地址访问。
绑定主机名时只信任配置的名称和实际绑定地址。`--host 0.0.0.0` 虽监听所有接口，
Host 仍只接受本机名称，不会自动信任任意域名或局域网地址。
不支持任意反向代理域名或 HTTPS Origin；公网部署需要另行设计认证与资源隔离，
详见 [安全说明](../SECURITY.md)。

可从 [合成示例](../examples/README.md)导入棋谱，无需模型或训练数据。

### Windows 终端退到后台时的性能

默认启动会为 **Web 服务自身** 设置进程和搜索线程 HighQoS，显式禁用执行速度节流，
并将 Normal/BelowNormal/Idle 优先级提高到 AboveNormal。保留用户已设置的更高优先级。
浏览器才是交互界面，终端失去焦点不应让它所承载的交互推理被当作节能后台任务。
微软说明窗口可见性与焦点会参与 [QoS 分类](https://learn.microsoft.com/en-us/windows/win32/procthread/quality-of-service)，
并提供了[显式关闭执行速度节流的 API](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-setprocessinformation)。
这与「网页在前台、终端在后台时 AZ 变慢」的反馈相符，但仅据现象不能断言具体驱动或调度环节的根因。

设置仅在本次进程内生效，退出时恢复；不写注册表、不改系统电源计划、显卡配置、CPU 亲和性，
不改训练、搜索预算、叶批或 PyTorch 线程数。可能增加后台计算时的耗电与风扇负担。
非 Windows 平台不调用这些接口；Windows 拒绝设置或不支持相关 API 时，保留可用能力并在启动时报告。

启动日志应包含：

```text
Scheduling: responsive; priority=above_normal; HighQoS=True
```

`GET /api/health` 的 `runtime` 字段返回设置回读；实际搜索后，`search_thread_high_qos` 应为 `true`。
`last_search.device` 显示真实使用的 `cuda` / `cpu`，`seconds` 记录引擎计算时间，
`result_wait_seconds` 记录计算完成到网页取走结果的等待时间。网页引擎状态显示计算设备，
悬停耗时可看到两段时间，便于区分计算变慢和刷新延迟。

可对照运行原系统调度：

```powershell
python web_server.py --scheduling system
```

只读短测（固定同一局面、模型、模拟次数、叶批和采样种子，预热后按 system / responsive / responsive / system 顺序）：

```powershell
python tools/probe_web_background.py --simulations 200 --leaf-batch-size 64 --repeats 3
```

该探针不会切换窗口焦点，因此验证的是调度策略对照，**不能冒充终端前后台切换的复现测试**。
本机 RTX 4060 Laptop / CUDA 短测两组都约 0.07–0.10 秒，未复现用户反馈的明显差异；
已确认显式 HighQoS、AboveNormal 和线程标记设置成功。实际终端切换效果需在新服务上复测。

## 已实现

- **人机对弈**：执红或执黑；执黑自动翻转。RIS-ISMCTS 不需要模型即可使用。
- **AlphaZero**：自动发现 `data/models` 和 `data/*/models` 中的 `latest.pt`、`best.pt`，
  排除 `legacy*` 目录，优先列出当前 `train_rules5_*` 权重。不读取完整训练检查点、不启动训练。
  历史非 legacy 目录仍可能包含旧版本权重，按项目已有的兼容加载路径读取，选择时核对目录来源。
- **自定义搜索预算**：对弈、分析分别填写 1–100000 的正整数模拟次数，不再限制于下拉预设。
  顶部「设置 → 对弈与新局 → 应用到当前对局」可在局中调整预算或引擎，取消旧对弈搜索并保留棋谱。
  预算是计算量，不是棋力等级。首次使用 AZ 需要载入模型，耗时取决于设备。
- **叶批大小**：对弈与分析分别配置 1–4096 的正整数。只对 AlphaZero 生效，实际叶批为
  `min(配置叶批, 模拟次数)`，界面同时显示实际值。调整模拟次数或叶批不会重复载入同一模型。
- **AI 分析面板**：棋盘下方提供唯一的「AI 提示」入口；右侧提供「评估局势」、推荐着法和红黑胜率条，
  支持自动提示和自动评估。「设置 → AI 分析」或分析面板齿轮可独立选择引擎、模型、模拟次数、叶批大小。
  对弈使用 RIS 时也可以用 AZ 分析；默认有权重时选择 AZ 分析，否则用 RIS 提示。
  RIS 不提供模型胜率，界面明确显示不可评估，不填入虚构的 50%。
  AZ 返回的行动方估计值转成固定红方/黑方视角显示，和棋折半计分。
- **好友切磋**：同屏双人，双方轮流落子；被吃暗子均使用公共视角。
- **观棋研习**：AI 自动对弈，开始时暂停，可随时暂停/继续。
- **交互**：合法落点、上一着、将军标识、走子提示、悔棋、认输、手动翻转棋盘。
- **棋谱**：点击历史走子，或用左右方向键复盘；分叉处选择下一步；从当前节点继续创建变例。
  悔棋不删除原走法，重新进入已有分支会复用原揭示结果。
- **棋谱导入**：复用 `GameRecord.from_dict`，读取 Python GUI 的 v1/v2 棋谱，按当前规则验证，
  v3/v4 规则迁移沿用 GUI 逻辑。导入后进入公共视角复盘。限制为 2 MB、2000 个节点。
- **棋谱导出**：未终局时下载 `jieqi-web-public` 公开记录，供查阅，不包含私有捕获类型，不能导入继续对弈。
  终局或认输后可导出 GUI 兼容的完整 `jieqi-replay` v2 棋谱。
  导出按钮明确标注「公开记录」或「完整棋谱」，是否允许完整导出以实际对局最新节点为准。
  点击历史走子不会截断导出：全部走子与分支仍保留，`cursor` 记录当前浏览位置，`web_head` 单独记录对局最新位置。
  网页导入后停在保存时浏览的位置，「回到最新局面 / 返回对局」可到达原来的最新节点。
  认输额外记在 `web_resignation` 元数据中，网页加载时恢复；旧版认输棋谱也可借此找回最新节点。
  Python GUI 会忽略网页专用的最新节点信息，仍按 `cursor` 打开，可继续研究棋盘局面。
  旧版不含这些信息的普通 GUI 棋谱沿用 `cursor` 作为保存位置；公开记录缺失的数据无法由此修复。
- **音效**：Web Audio 在本机合成选子、落子、吃子、将军、胜负与和棋音效。顶部扬声器打开 0–100% 音量滑块，
  提供静音和落子试听，音量自动记住；默认 80%，整体响度比旧版提高。调大滑块会解除静音。
  遵循浏览器音频策略，首次点击或键盘交互后启用。无外部音频、字体或 CDN 请求。
- **布局**：1200px 及以上为三栏：棋盘、吃子与分析、独立棋谱。棋谱列表单独滚动，底部导航常驻；
  961–1199px 改为两栏，更窄屏幕使用单列。导入棋谱和玩法指南固定在顶部；
  低频参数集中到设置弹窗。双方信息合并为棋盘顶部一行，行动方卡片加边框，标签明确写出红方/黑方；
  暂停指整个对局，顶部和棋盘状态注明暂停后等待哪方行棋。
  棋盘同时受可用宽度和高度约束。100% 浏览器缩放下验证 1024×768、1366×768、1536×864、
  1920×1080，完整显示棋盘与底部操作。手机依次显示吃子、棋盘、辅助面板。
- **吃子常驻**：独立显示双方吃子总数，棋子按吃子顺序逐枚排列、标注发生手数，相同身份也不合并。
  最近一次吃子加亮并单独显示吃方、手数与被吃身份，点击棋子可回到对应节点。未知身份仍显示「暗」。
  导入初始局面已有的吃子注明「已有」，不编造手数；复盘和分支只展示当前路径的吃子。
  吃子不随辅助栏滚走，也没有隐藏开关；手机上固定在顶栏下方。身份可见范围仍沿用原规则。
- **标记分层**：绿色圆点/虚线圈表示合法落点；蓝色箭头、起点描边和落点菱形表示 AI 推荐；
  紫色虚线起点、实线落点与棋子描边表示上一着，红色表示将军。棋盘翻转时标记同步变换。
- **显示选项**：顶部「显示」可选择分析面板、棋谱与局面、引擎运行详情、合法落点、上一着标记、棋盘坐标。
  默认隐藏运行详情；对弈错误时自动显示以便重试。隐藏分析面板不会更改自动分析开关。
  适配触摸、键盘焦点和减少动态效果的系统设置。
- **记住设置**：应用后的对弈模式、执子、引擎、模型、模拟次数、叶批大小，以及独立分析配置、自动分析开关、
  显示选择、音效开关和音量均保存在当前浏览器。同一来源（协议、主机、端口）下刷新或重启服务后继续使用；
  已有对局以服务端参数为准，不会被旧偏好覆盖。保存的模型不存在时回退到 RIS，保留其他参数并提示。
  尚未应用的编辑不保存；浏览器禁止本地存储时仅本次有效。

## 数据与规则

对局保存在服务进程内，浏览器使用 HttpOnly / SameSite 会话 Cookie。刷新页面继续原局；
不同浏览器会话互相独立，同一浏览器的标签页共享一局，写入时用 `revision` 防止过时操作。
会话闲置超过 12 小时或停止服务后不再保留。重新开局和导入前，如果已有棋谱，界面会提醒导出。
未完成对局的公开导出不包含恢复完整对局所需的私有信息；需要长期保存完整研究棋谱时，可在终局后导出。
浏览器本地偏好只保存上述设置，不包含棋谱、棋盘或私有身份；它不能在服务重启后恢复原对局。

规则直接使用 `jieqi.py`，棋谱直接使用 `game_record.py`，搜索直接使用 `ismcts.py` 与
`search_engine.AzEngine`，任务取消复用 `gui_tasks.py`。没有另写浏览器规则，也没有修改算法、训练、
检查点、现有 GUI 或规则裁判的实现。

客户端只拿到公开棋盘、合法着法和当前视角允许看到的吃子记录，不接收真实暗池、信念模型、
预设暗子布局或私有捕获揭示。人机模式下只有吃方玩家能看到自己吃掉的暗子类型；
双人及 AI 观棋模式不向公共视角显示未终局的私有吃子身份。现有项目近似裁判的限制继续适用。

搜索不阻塞 HTTP 线程；每个会话有独立的对弈和分析通道，各自串行、各自复用引擎与 RNG。
提示/评估不占用对弈通道，分析中仍可手动落子。分析失败不暂停对局，也不自动无限重试。
重开、悔棋、暂停和复盘均取消过时任务，落子会取消旧节点分析。
分析结果按棋谱实例、节点、引擎、模型文件时间/大小、模拟次数、叶批配置缓存（最多 32 项），
只在完全匹配时作为当前分析结果接收。前端在等待新节点评估时保留上一份红黑胜率，
明确标注「正在更新 / 当前局面待评估 / 更新失败」与旧结果来源手数；新结果返回后直接替换，胜率条平滑过渡。
旧结果不恢复推荐着法，也不传回后端。新开局、导入、更换分析引擎/模型/预算/叶批会清除该显示记忆；
终局直接显示终局结果，回看时不会把终局百分比带回普通局面。
模型载入或 GPU 前向结束后才到达协作取消边界。
AI 对局通过页面轮询推进；后台标签页停止轮询，回到页面后继续推进，不是无人值守赛事调度器。

## HTTP 接口

请求与响应都是 JSON，同源 Cookie 标识会话；不提供跨域访问。所有写入必须带最近状态的整数 `revision`。
状态中 `side` / `human_side`：红为 `1`，黑为 `0`；棋盘索引为 `row * 9 + col`，从黑方底线左侧开始。
棋子编码沿用 `jieqi.py`；暗子的类型字段仅为其初始假类型。

| 接口 | 方法 | 说明 |
| --- | --- | --- |
| `/api/health` | GET | 服务状态和规则版本，不创建对局 |
| `/api/config` | GET | 引擎和可用纯权重路径列表 |
| `/api/state` | GET | 状态、合法着法、棋谱、搜索进度；接收后台结果并按需启动下一步 |
| `/api/new` | POST | `mode: human/local/aiai`、`human_side`、`engine: ris/az`、`model`、`simulations`、`leaf_batch_size` |
| `/api/settings` | POST | 局中更新对弈 `engine/model/simulations/leaf_batch_size`，保留棋谱 |
| `/api/analysis-settings` | POST | 独立更新分析 `engine/model/simulations/leaf_batch_size/auto_hint/auto_evaluate` |
| `/api/move` | POST | `from`、`to`；服务端再次验证合法性、回合和终局状态 |
| `/api/hint` | POST | 当前信息下的异步推荐；通过状态轮询读取 `hint` |
| `/api/evaluate` | POST | 异步 AZ 局势评估；通过 `analysis` 和 `analysis_pending` 读取结果 |
| `/api/undo` | POST | 人机退回上一轮玩家行动前，其他模式退一手；保留棋谱分支 |
| `/api/navigate` | POST | `cursor` 节点编号，进入复盘并停止自动落子 |
| `/api/resume` | POST | 回到当前对局最新节点，或重试失败搜索 |
| `/api/continue` | POST | 从当前复盘节点继续，保留其他分支 |
| `/api/pause` | POST | 切换暂停状态，取消在途搜索 |
| `/api/resign` | POST | 人机模式玩家认输 |
| `/api/import` | POST | `record` 完整 GUI 棋谱对象；逐着验证成功后替换会话 |
| `/api/export` | GET | 未终局公开记录，终局完整棋谱 |

响应 `outcome`：`null` 未终局，`1` 红胜，`-1` 黑胜，`0` 和棋。`pending` 为对弈搜索，
`analysis_pending` 为独立分析任务。`analysis` 带当前 `node`、`move`、`label`、预算和实际叶批，
`red_win_rate/black_win_rate` 为固定红黑视角；`win_rate` 为根行动方估计。
RIS 的胜率字段为 `null`；分析异常单独使用 `analysis_error`，对弈异常仍使用 `error`。
`last_search.win_rate` 记录该次对弈搜索行动方的估计，不用于当前局面的评估条。
参数、非法着法、棋谱错误或过时 revision 返回 `400` 和中文 `error`。跨域写入返回 `403`。
`preferences_ready` 仅在服务新建、尚无成功写入的会话中为 `false`，允许前端恢复本地参数；
任意成功操作后为 `true`，包括显式新建的空棋谱，避免刷新时覆盖用户刚选择的配置。
`record_id` 是当前棋谱实例的随机标识，新开局/导入时更换，普通操作不变，供前端隔离显示记忆。
`captured` 中每枚棋子保留过滤后的 `side/dark/type`，补充发生吃子的 `node/depth/source/target`；
初始局面已有吃子的 `node/depth` 为 `null`，不包含私有揭示字段。
`export_format` 表明当前可下载 `jieqi-web-public` 公开记录还是 `jieqi-replay` 完整棋谱，与当前复盘光标是否终局无关。
完整棋谱额外保存 `web_head`；导入前校验节点范围、认输方与认输节点，异常时保留现有对局。

后续新增引擎可在 `WebGame.start_search` 的后台适配器中接入：输入克隆的 `state`、
`SearchBelief` 包装后的 `belief` 和最近八手 `(from, to)` 历史，输出
`{"move": (from, to), "value": win_rate_or_none}`。不要将服务端私有状态直接序列化给浏览器。

### 算法接口核对

这些界面与参数需求不需要算法侧新增接口或调整训练。现有 `ISMCTSConfig.iterations` 支持自定义模拟次数；
`search_engine.AzEngine.analyse(..., simulations=...)` 已支持搜索推荐和根价值估计；
`AzEngine.config.leaf_batch_size` 对应 `azero.NeuralMCTS.search` 使用的叶批配置。
Web 适配器在每次任务开始时设置叶批，同 GUI 的调用方式一致。
输入仍为克隆局面、行动方信息集及最近八手 `(from, to)`，没有把前端显示需求转成新的算法或棋力保证。
