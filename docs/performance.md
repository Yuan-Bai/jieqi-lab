### 机会节点默认值与续训

训练、GUI 和独立评估都通过 `AZConfig` 使用新默认值：`chance_nodes=True, chance_k=0` 时按需分配对象。
所有合法动作边仍在扩展时创建；机会结果从完整模拟世界暗池抽样，原始先验、枚举序号、RNG、网络批次和信息集共享不变。
这不是降低模拟预算或截断机会支持。

- 原 on/k=0 续训命令无需追加参数；新进程会启用按需分配。运行中的进程不会热切换。
- `--no-lazy-chance-allocation` 恢复原 k=0 全量预建，便于排查与配对测试。
- `--no-chance-nodes` 或 `--chance-k K`（K>0）自动沿用各自旧路径，不启用这个对象分配优化。
- 显式 `--lazy-chance-allocation` 与 off/k>0 组合仍报错，避免把它与 k>0 的预建子集混淆。
- Python API 中，省略该字段或传 `None` 按机会配置解析为 bool；传 `False` 回退；显式 `True` 的不兼容配置由 `NeuralMCTS` 拒绝。
- 当前 v5 完整检查点、optimizer、scheduler、RNG 和 replay 可继续使用；旧检查点保存的 `False` 不会覆盖本次 CLI 配置。不需要重训、清空 buffer 或 `--reset-optimizer`。
- `RULESET_VERSION=5, DATA_VERSION=3, SEARCH_VERSION=3` 不变。旧规则目录的兼容性限制仍然存在。

日志应显示“完整揭示支持，按需分配对象”；新运行的 manifest 记录解析后的布尔配置。
辅助工具需要观察完整物理树时可调用 `materialize_chance_outcomes`；未补全树的节点数/序列化不是搜索语义等价判据。

### 编译后端

后端只在导入时选择。规则后端自动启用；合法着快路仍需显式选择，节点后端继续保留 Python：

```powershell
$env:JIEQI_LEGAL_BACKEND='cython'
$env:JIEQI_SEARCH_BACKEND='python'
python -c "import jieqi, azero; print('rules:', jieqi.RULES_BACKEND); print('legal:', jieqi.LEGAL_BACKEND); print('nodes:', azero.SEARCH_BACKEND); print('lazy chance:', azero.AZConfig().lazy_chance_allocation)"
```

缺少扩展时先构建需要的模块。运行时无需 Cython，不会自动构建或下载：

```powershell
python -m pip install --target data/build_deps Cython==3.3.0
python tools/build_rules.py
python tools/build_legal.py
python -m pytest -q test_native_rules.py test_native_legal.py
```

Windows 需要 Visual C++ 构建工具；其他平台需要适配当前 Python 的 C 编译器。
`.pyd`/`.so` 和构建产物不入库；Python ABI、平台、原生源码或受保护方法指纹变化后应重建。
`python` 强制回退，`auto` 有效则启用，否则回退，`cython` 缺失/过期则报错。
各后端独立校验版本、源/方法指纹，并在运行记录中保存实际加载路径和二进制哈希。
独立节点实验构建入口是 `tools/build_search.py`，不属于推荐训练配置。

2026-10-08新增机会表复用只编译整数快照防护，概率运算仍用原 Python。
本机规则扩展已重建；其它工作区若仍有旧规则二进制，应运行 `python tools/build_rules.py`。
源码哈希不符时 `auto` 回退、显式 `cython` 报错，不能把旧二进制当已启用新加速。
合法着/节点方法指纹未改；新进程生效，不热切换运行中的训练，无新训练 CLI 参数。
